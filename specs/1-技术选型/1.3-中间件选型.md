## 1. 选型原则

| 原则 | 说明 |
|---|---|
| 职责明确 | 每个中间件只做自己最擅长的事，不让一个组件承担多种不相关职责 |
| Java 侧统一治理 | MQ、缓存、任务调度由 Java 侧统一管理，Python 侧专注 AI 逻辑 |
| RAG 归口统一 | 检索路由、候选合并和重排统一由 LlamaIndex 承接，不分散 |
| 可追踪优先 | 检索、召回、评分过程需要支持回放和审计 |
| 可替换 | 中间件之间通过接口解耦，避免单点绑定 |

## 2. 中间件清单

> 各中间件承载的具体表与节点设计见 [2.1 存储架构总览](../2-数据模型/2.1-存储架构总览.md)。

### 2.1 主业务数据库 — MySQL

由 Java Spring Boot 管理。承载所有业务主表（题库、用户、会话、学习记录、采集任务、抽取运行、向量投影元数据等）。

- Java 侧通过 Spring Data JPA / MyBatis 访问。
- Python 侧需要读写 MySQL 时，通过 Java 提供的 HTTP API 间接访问，或使用 PyMySQL 直连（仅在明确需要时）。

### 2.2 知识图谱数据库 — Neo4j

承载知识图谱（Question / Concept / Domain / Tag / Company / Position 节点及关系）和向量索引（embedding 存于 `Question` 节点）。

- Python 侧（LlamaIndex）直接访问 Neo4j。
- Java 侧通过 Python API 或 Neo4j Java Driver 访问。

> 详细 Schema 见 [2.3 Neo4j 图谱 Schema](../2-数据模型/2.3-Neo4j图谱Schema.md)。

### 2.3 消息队列 — RabbitMQ

由 Java Spring Boot 管理，承担**爬取任务下发、LLM 抽取削峰、异步解耦**等任务。

队列清单详见 [3.1 §8](../3-后台流水线/3.1-爬取与抽取流水线.md)、[3.2 §10](../3-后台流水线/3.2-图谱构建流水线.md)、[3.3](../3-后台流水线/3.3-相似归组流水线.md)、[3.4 §4](../3-后台流水线/3.4-向量索引流水线.md)。

死信队列（DLQ）由 [7.3 告警与处置手册](../7-运维与可观测/7.3-告警与处置手册.md) 定义重试与告警策略。

### 2.4 缓存 — Redis

| 用途 | 说明 |
|---|---|
| 会话缓存 | 用户 token、会话状态 |
| 接口限流 | API 级别的请求频率控制 |
| 热点题目缓存 | 高频访问的题目列表、分页结果 |
| 分布式锁 | 防止同一 URL 被并发重复下发 |
| 任务状态缓存 | 爬取任务 / 抽取任务的实时状态查询 |

Java 侧通过 Spring Data Redis 管理。

### 2.5 向量库（按需引入） — Qdrant

当 Neo4j 向量检索规模或性能成为瓶颈时引入：
- 支持大规模 ANN（近似最近邻）检索。
- 支持混合检索（向量 + 结构化 payload 过滤）。
- LlamaIndex 有原生 Qdrant 集成，切换成本低。

引入信号：题目量超过 50 万，或 Neo4j 向量检索延迟超过可接受阈值。

### 2.6 可观测性 — 结构化日志 + OpenTelemetry

| 组件 | 用途 |
|---|---|
| 结构化 JSON 日志（`trace_id` 字段） | 所有服务统一日志格式，便于跨服务关联 |
| OpenTelemetry SDK | Java 和 Python 两侧统一接入，产出 Trace |
| Jaeger / Tempo | Trace 可视化，调用链排查 |
| Loki | 日志聚合，配合 Grafana |

`trace_id` 在 Java 侧生成，通过 HTTP Header 和 MQ Message Header 传递到 Python 侧，保证全链路可追踪。详细方案见 [7.1 可观测性设计](../7-运维与可观测/7.1-可观测性设计.md)。

## 3. 服务间通信

| 通信方式 | 使用场景 |
|---|---|
| HTTP / REST | Java 同步调用 Python（RAG 查询、Playground 实验触发、向量检索） |
| RabbitMQ | 异步任务：爬取、抽取、归组、向量构建 |
| Neo4j Bolt | Python 直连 Neo4j（图谱查询、向量检索） |
| MySQL JDBC / PyMySQL | Java 主连接，Python 按需直连或走 Java API |

---

## 4. 分阶段落地

### 阶段 1：核心链路跑通

- MySQL + Neo4j + RabbitMQ + Redis 全部就位。
- Java 侧：Spring Boot 主服务、RabbitMQ 任务调度、MySQL CRUD、Redis 缓存。
- Python 侧：AgentScope 编排、LlamaIndex RAG、抽取服务、归组服务。
- 结构化 JSON 日志打通 trace_id。
- Qdrant 暂不引入。

### 阶段 2：可观测性完善

- 引入 OpenTelemetry SDK（Java + Python 双侧）。
- 配置 Jaeger/Tempo 和 Loki + Grafana。
- 建立 `retrieval_event` 表（详见 [2.10](../2-数据模型/2.10-审计与检索事件表.md)），记录 query、召回候选、分数、重排结果。

### 阶段 3：规模扩展

- 根据 Neo4j 向量检索压力决定是否引入 Qdrant。
- 根据消息量决定是否从 RabbitMQ 升级到 Kafka。
- 根据分析需求决定是否引入 ClickHouse 做离线分析。
