# AgentScope + LlamaIndex MVP 架构验证报告

更新时间：2026-05-08
文档状态：验证完成

---

## 1. 验证目标

验证 AgentScope 作为 Python Agent 编排层、LlamaIndex 作为独立检索层，是否能够支撑面经问答场景的最小闭环，并确认脚本在当前 Windows 环境下可运行。

## 2. 验证对象

| 项目 | 内容 |
|---|---|
| 演示脚本 | [demos/agent_scope_llamaindex_mvp/mvp.py](../../demos/agent_scope_llamaindex_mvp/mvp.py) |
| 依赖清单 | [demos/agent_scope_llamaindex_mvp/requirements.txt](../../demos/agent_scope_llamaindex_mvp/requirements.txt) |
| 运行环境 | Windows |
| Python 解释器 | C:\Users\Wangxr\miniconda3\python.exe |
| 关键依赖 | agentscope 1.0.19.post1 / llama-index-core 0.14.21 / llama-index-retrievers-bm25 0.7.1 |

## 3. 验证步骤

1. 安装演示依赖。
2. 执行演示脚本。
3. 观察两轮输出是否与知识库内容匹配。
4. 记录运行时警告和可用性结论。

## 4. 验证观察

| 问题 | 观察结果 |
|---|---|
| AgentScope 和 LlamaIndex 在系统里分别负责什么？ | 检索结果能够正确召回“AgentScope 负责编排与轨迹记录”“LlamaIndex 负责检索与召回”两类知识片段。 |
| 需要记录可追踪的检索轨迹时应落库什么？ | 检索结果能够正确召回 query、召回候选、分数、重排结果、模型版本、prompt 版本、trace_id。 |
| Windows 下是否能运行？ | 可以运行；启动时出现 resource module not available on Windows 的提示，但不影响脚本完成两轮输出。 |

## 5. 结论

- 最小闭环成立，演示脚本能够稳定输出检索结果和建议。
- AgentScope 与 LlamaIndex 的职责边界清晰，适合作为后续正式系统的分层基础。
- 当前实现适合做概念验证和接口雏形，不适合直接作为生产级实现。

## 6. 后续建议

- 用真实模型适配层替换当前确定性回答模型。
- 将检索事件单独落库，并与 trace_id 关联。
- 为 Java 主服务提供标准 HTTP 接口。
- 在向量检索、BM25 和混合检索之间做进一步对比。

## 7. 结论摘要

这次验证确认了一个可执行的架构方向：Java 主服务负责业务治理，Python 侧 AgentScope 负责多步骤编排，LlamaIndex 负责检索与召回，审计和追踪信息需要独立保存。
