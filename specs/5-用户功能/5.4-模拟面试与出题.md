## 1. 功能概览

本功能包含两种独立模式，使用不同界面，互不干扰：

| 模式 | 界面 | 特点 | AgentScope |
|---|---|---|---|
| **全追问模拟面试** | 对话式 | Interviewer Agent 主持，实时追问，Evaluator Agent 逐题评分 | ✅ 双 Agent |
| **纯出题练习** | 表单式 | 依次出题，用户填写答案，LLM 评分，无对话 | ❌ 直接调用 LLM |

LLM 生成的补充题目，用户可以会后"贡献到题库"——形成题库 → 面试 → 新题库的正向循环。

## 2. 面试配置维度

| 配置项 | 是否必选 | 选项 | 说明 |
|---|---|---|---|
| `position`（岗位） | **必选** | Java 后端、算法工程师、大模型工程师、全栈…… | 决定题目方向 |
| `company`（公司） | 可选 | 字节/阿里/腾讯/美团…… | 优先出该公司真题 |
| `round_type`（轮次） | 可选 | 一面技术 / 二面深度 / 系统设计 / HR 面 | 影响题目深度和类型 |
| `difficulty`（难度偏好） | 可选 | 初级 / 中级 / 高级 / 混合梯度 | 默认混合梯度 |
| `domains`（知识领域） | 可选 | 从 Domain 节点多选，如 [Java, MySQL, Redis] | 手动指定侧重点 |
| `question_count`（题目数量） | 可选 | 5 / 8 / 10 / 自定义 | 默认 8 道 |
| `time_limit`（时间限制） | 可选 | 30 / 45 / 60 分钟 / 不限 | 模拟真实面试节奏 |

## 3. 出题策略（GraphRAG 驱动的复合逻辑）

### 3.1 总体流程

```
用户配置（岗位必选，其他可选）
        │
        ▼
① GraphRAG 概念映射：岗位 → 核心概念集合
        │  从 Neo4j 找该岗位题目最多覆盖的概念，取 top-N
        │
        ▼
② 概念配额分配：把 question_count 分配到各概念
        │  确保覆盖度，不让某一概念独占所有题目
        │
        ▼
③ 题目选取（每个概念配额内）
        │  过滤：公司匹配、难度梯度、排除近期已做题
        │  排序：优先公司真题 > 高质量题 > 创建时间新
        │
        ▼
④ 缺口检测：某概念题库不足时，LLM 补充生成
        │
        ▼
⑤ 全局排序：按难度梯度（易 → 中 → 难）重新排列
        │
        ▼
⑥ 生成会话题目计划（写入 mock_interview_questions 表）
```

### 3.2 GraphRAG 概念映射（Cypher）

```cypher
// 给定岗位，找高频覆盖概念
MATCH (p:Position {name: $position})<-[:FOR_POSITION]-(q:Question)
-[:COVERS_CONCEPT]->(c:Concept)
WHERE q.status = 'active'
WITH c, count(q) AS coverage
ORDER BY coverage DESC
LIMIT 15
RETURN c.name AS concept, coverage
```

> 详细查询模式见 [4.2 GraphRAG 查询模式](../4-检索召回/4.2-GraphRAG查询模式.md)。

### 3.3 概念配额分配规则

```
目标题数：question_count = 8

基础分配：top-5 概念各 1 题 = 5 题
剩余 3 题：分给 coverage 最高的 3 个概念（各 +1）

如用户指定 domains：该 domains 内的概念配额优先保证，其余概念从剩余配额里补
```

### 3.4 难度梯度排序

```
题目排序：
  位置 1-2：简单题（热身）
  位置 3-5：中等题
  位置 6-7：较难题
  位置 8：最难题（压轴）

如 difficulty = 初级：所有题都从简单/中等选
如 difficulty = 高级：跳过简单，从中等/难选
如 difficulty = 混合梯度（默认）：按上述排序
```

### 3.5 LLM 补充生成触发条件

```
当某概念配额 = 2，但题库只有 0 题：
  → 触发 LLM，传入 concept + position + round_type
  → LLM 生成 2 道题（含参考答案）
  → 临时存入 mock_interview_questions（question_source = 'llm_generated'）
  → q_id 为空，不自动写入 questions 主表
  → 会后用户可选择"贡献到题库"
```

## 4. 模式一：全追问模拟面试

### 4.1 面试流程状态机

```
session.status:
  draft        → 配置完成，未开始
  in_progress  → 面试进行中
  paused       → 用户暂停（可继续）
  completed    → 所有题目结束
  reported     → 报告已生成

question.status（每道题）:
  pending      → 等待出题
  in_progress  → 正在讨论（含追问轮次）
  evaluated    → 已评分
  skipped      → 用户跳过
```

### 4.2 Agent 分工

| Agent | 职责 | 触发时机 |
|---|---|---|
| **Interviewer Agent** | 主持面试：出题、分析回答、决定追问、过渡到下一题 | 会话全程 |
| **Evaluator Agent** | 评分：正确性/完整性/深度/表达，给出要点缺失反馈 | 每道题全部轮次结束后 |

**两个 Agent 通过 AgentScope 消息传递协作**：

```
Interviewer Agent ─── "请评分这道题" ──→ Evaluator Agent
                  ←── 评分结果 ─────────
Interviewer Agent ─── 展示评分，进入下一题
```

### 4.3 Interviewer Agent 决策逻辑

```
用户回答后：

1. 分析回答质量（LLM 判断，短 prompt）：
   - 回答完整 & 准确 → 不追问，进入下一题
   - 回答表面/缺关键点 → 追问（最多 2 轮）
   - 回答错误/偏题 → 追问并给方向提示

2. 追问生成策略：
   - 用户说"知道 IOC 是控制反转" → 追问"能说说 Spring 容器是怎么实现控制反转的吗？"
   - 用户答了 BeanFactory → 追问"和 ApplicationContext 有什么区别？"
   - 追问内容来自：(当前题覆盖概念的子概念) + (用户提到但未展开的点)

3. 追问上限：每道主题最多追问 2 次，超过后强制进入下一题

4. 跳过处理：用户可主动跳过，status = skipped，评分记 0
```

### 4.4 Evaluator Agent 评分维度

| 维度 | 满分 | 说明 |
|---|---|---|
| 正确性 | 10 | 核心知识点是否答对，无明显错误 |
| 完整性 | 10 | 是否覆盖了参考答案的主要要点 |
| 深度 | 10 | 是否有原理层面的理解，不只是表面定义 |
| 表达 | 10 | 逻辑是否清晰，有无自相矛盾 |

综合分 = (正确性×0.35 + 完整性×0.30 + 深度×0.25 + 表达×0.10) × 10

### 4.5 每题结束后的实时反馈展示

```
┌─────────────────────────────────────────┐
│ 本题评分                                │
│ 正确性 ████████░░  8/10                 │
│ 完整性 ██████░░░░  6/10                 │
│ 深度   ████░░░░░░  4/10                 │
│ 表达   █████████░  9/10                 │
│ 综合分：6.85 / 10                       │
│                                         │
│ 你遗漏的关键点：                        │
│ ✗ MVCC 的具体实现（Read View 机制）     │
│ ✗ 可重复读隔离级别下的幻读问题          │
│                                         │
│ 参考答案要点 ▸（可展开）                │
└─────────────────────────────────────────┘
```

### 4.6 面试结束报告

```
整体评分：7.2 / 10

知识域表现：
  Java 并发  ██████████  9.2  ✅ 优秀
  Spring     ████████░░  7.8  ✅ 良好
  MySQL      ██████░░░░  6.1  ⚠️ 待加强
  Redis      ████░░░░░░  4.5  ❌ 薄弱

面试官评语：（Interviewer Agent 生成的整体印象）
"候选人对 Java 并发机制掌握扎实，能够清晰阐述锁的升级过程。

推荐复习：
  → MySQL 事务与 MVCC（8 道相关题）
  → Redis 集群与哨兵模式（5 道相关题）
```

## 5. 模式二：纯出题练习

界面无对话，流程简单：

```
出题 → 用户填写答案 → 提交 → LLM 评分 → 看反馈 → 下一题
```

- 无 Interviewer Agent，无追问
- 同样使用 GraphRAG 复合选题逻辑
- 支持"查看参考答案"（提交后可见）
- 适合自测、快速刷题

## 7. AgentScope 实现结构

### 7.1 Interviewer Agent

```python
InterviewerAgent:
  输入：session_plan（题目列表）、interviewer_style
  
  核心方法：
    start_session()     → 开场白 + 第一道题
    process_answer(user_msg)
      → analyze_answer_quality()   # 短 LLM 调用，判断是否需要追问
      → if needs_followup and followup_count < 2:
            generate_followup()    # 追问
        else:
            notify_evaluator()     # 通知 Evaluator 评分
            next_question()        # 下一题
    end_session()       → 结束语 + 触发报告生成
    
  状态跟踪：
    current_q_index, followup_count, turn_history
```

### 7.2 Evaluator Agent

```python
EvaluatorAgent:
  输入：session_question（题目+参考答案）、turn_history（全部对话轮次）
  
  核心方法：
    evaluate(session_question, turn_history)
      → compile_full_answer(turn_history)   # 合并用户的所有轮次回答
      → llm_score(question, reference, full_answer)
      → return EvaluationResult(scores, missed_points, feedback)
      
  输出写入：mock_interview_evaluations 表
  触发时机：每道题的所有轮次结束后（由 Interviewer Agent 通知）
```

### 7.3 消息流

```
[用户] 回答
  → [Interviewer Agent] 分析质量
      ├─ 需要追问 → 生成追问 → 展示给用户
      └─ 不追问   → 发消息给 Evaluator Agent
                    [Evaluator Agent] 评分 → 写库
                    → 把评分发回给 Interviewer Agent
                    → Interviewer Agent 展示评分 → 进入下一题
```

## 8. LLM 生成题的生命周期

```
面试中生成
    │
    ▼
存入 mock_interview_questions（question_source = llm_generated，q_id = NULL）
    │
    ▼
面试结束后，用户在报告页看到 LLM 生成的题目
    │
    ├─ 用户点击"贡献到题库"
    │       → 写入 extracted_question_items（手动创建 run 记录）
    │       → 走正常 canonical 化流程 → questions 表
    │       → mock_interview_questions.contributed_to_bank = 1
    │
    └─ 用户不贡献 → 仅留存于历史记录
```

## 10. 里程碑

| 里程碑 | 内容 |
|---|---|
| M1 | 纯出题练习模式上线（无 Agent，基础 GraphRAG 选题，LLM 评分） |
| M2 | Interviewer Agent + Evaluator Agent 上线（全追问面试模式） |
| M3 | 面试报告生成（知识域分析 + 推荐复习） |
| M4 | LLM 生成题的"贡献到题库"流程打通 |
| M5 | study_review_logs 回写，面试历史影响复习调度；低分题入错题本 |
