## 1. 功能背景与目标

当前抽取链路的核心痛点：

- Prompt 内容散落在代码里，没有版本记录，改坏了不知道怎么回滚。
- 换了模型或调了参数，无法对比前后的抽取质量。
- 抽取结果有错的时候，只能改代码重跑，没有一个"在线修正 + 观察"的入口。
- 不同 prompt 版本对同一篇帖子的抽取结果，很难并排对比。

**本功能的目标**：

1. 对 Prompt 实现版本化管理，每次修改都可以保存、查看、对比和回滚。
2. 提供"抽取 Playground"入口：选择任意一篇已爬取的帖子 + 任意一个 prompt 版本 + 任意模型，一键重新抽取，观察结果。
3. 前端可以对抽取结果进行人工修正，修正记录和 prompt 版本关联，方便判断"哪个版本的 prompt 抽出来的更准"。
4. 支持把"修正后的题目"直接推送到 canonical 题库（`questions` 表）。

## 2. 功能模块拆解

### 2.1 Prompt 模板管理

- 创建、编辑、查看 prompt 模板。
- 每次"保存"都产生一个新版本，旧版本只读不可修改。
- 模板分类（如 `question_extraction`、`answer_refinement`、`interviewer`、`evaluator`），便于扩展到不同类型的抽取/对话任务。
- 支持标记"默认版本"，生产链路的抽取始终使用默认版本。

### 2.2 模型配置绑定

- 每个 prompt 版本可以绑定一个"模型配置"（provider + model_name + llm_params）。
- 也可以在 Playground 里临时覆盖模型配置，不影响版本记录。
- 常用模型配置可以预设，不用每次手动填。

### 2.3 抽取 Playground

- 输入：选择一篇帖子（`source_links`）或直接使用已有的 `crawl_artifacts`，选择一个 prompt 版本，选择或覆盖模型配置。
- 操作：一键触发重新抽取（不写入生产题库，只写入实验表）。
- 输出：实时或准实时展示抽取结果（题目列表，含题干、答案、标签、置信度等）。
- 历史：每次实验的输入、输出、耗时、费用都记录下来，随时可以查看回放。

### 2.4 结果修正与标注

- 对 Playground 产出的每道题，支持：
  - 接受（标记为 `accepted`）。
  - 拒绝（标记为 `rejected`，填写拒绝原因）。
  - 修正（编辑题干、答案、标签等字段，保存为修正版）。
- 修正记录和"哪个 prompt 版本 + 哪个模型"绑定，方便对比不同版本的修正率。

### 2.5 推送到题库

- 对"接受"或"修正后"的题目，支持一键推送到 canonical 题库（写入 `questions` 表）。
- 推送时会做 `origin_item_id` 的唯一性检查，避免重复入库。
- 推送来源记录：题目知道自己是从哪次实验里来的（`promoted_q_id` 反查）。

## 3. 数据流

```
crawl_artifacts (已有页面文本)
       │
       ▼
prompt_versions (选择 prompt 版本 + 模型配置)
       │
       ▼
extraction_experiments (实验运行记录)
       │
       ▼
experiment_items (实验产出的题目列表)
       │
       ├── item_corrections (人工修正记录)
       │
       └── [推送] → questions (canonical 题库)
```

生产链路（`question_extraction_runs` + `extracted_question_items`）与实验链路（`extraction_experiments` + `experiment_items`）完全分离，互不污染。

## 5. 前端功能点清单

### 5.1 Prompt 管理页

| 功能 | 说明 |
|---|---|
| 模板列表 | 按 `template_type` 分类展示所有模板及其最新版本 |
| 版本历史 | 点击模板查看所有版本，支持版本对比（diff 视图） |
| 新建版本 | 在最新版本基础上编辑，保存即产生新版本，填写 change_note |
| 设置默认版本 | 将某个版本标记为生产默认，影响生产链路 |
| 模型配置 | 每个版本可绑定模型供应商、模型名、temperature 等参数 |
| 归档模板 | 对不再使用的模板做归档（`is_active = 0`） |

### 5.2 Playground 页

| 功能 | 说明 |
|---|---|
| 选择输入 | 从 `source_links` 搜索帖子，或直接输入文本（会创建临时 artifact） |
| 选择 prompt 版本 | 下拉选择模板和版本 |
| 选择模型 | 可复用版本绑定的模型，也可临时覆盖 |
| 一键运行 | 触发实验，loading 状态展示，完成后展示题目列表 |
| 历史实验列表 | 按帖子 / 按 prompt 版本筛选历史实验，点击查看结果 |
| 并排对比 | 选择同一帖子的两次实验（不同 prompt 版本 / 不同模型），并排展示题目列表 |
| 费用与耗时 | 每次实验展示 token 数、费用估算、耗时 |

### 5.3 结果审核页（可内嵌在 Playground 里）

| 功能 | 说明 |
|---|---|
| 题目列表 | 展示当次实验的所有抽取题目，含置信度 |
| 接受 / 拒绝 | 对每道题打标，拒绝时可填理由 |
| 在线修正 | 点击编辑题干、答案、标签、难度等字段，保存为修正记录 |
| 修正历史 | 查看该题目历次修正记录 |
| 推送到题库 | 对接受或修正后的题目，一键推送到 `questions` 表 |
| 修正统计 | 当前 prompt 版本的接受率、拒绝率、修正率，辅助判断 prompt 质量 |

---

## 6. 生产链路的最终对接

生产链路（`question_extraction_runs`）目前用 `prompt_version` 字符串记录版本，后续可以：

- 把 `prompt_version` 字段改为 `version_id`（外键到 `prompt_versions`）。
- 这样生产运行记录就和 prompt 版本管理完全统一，实现"知道每道生产题是哪个 prompt 版本抽出来的"。

这个改造不需要立即做，可以作为下一个迭代点。

---

## 7. 本功能不包含的内容（边界说明）

| 不包含 | 原因 |
|---|---|
| 批量跑多帖子 × 多版本的矩阵实验 | 是"评估框架"的职责，后续单独设计 |
| Prompt 的自动优化（DSPy 等） | 暂不引入，先把人工优化的工具做好 |
| 多用户协作编辑 prompt | 个人管理后台场景，不需要 |
| 版本 rollback 到生产 | 直接在前端重新"设置为默认版本"即可 |

---

## 8. 后续可扩展的方向

- **修正数据积累后**：把 `item_corrections` 里的"原始 → 修正"对作为微调样本，进行 Prompt 的半自动优化。
- **A/B 测试框架**：对同一批帖子并发运行两个 prompt 版本，统计各自的接受率，自动比较哪个版本更好。详见 [8.3 Prompt 质量评估](../8-治理与质量/8.3-Prompt质量评估.md)。
- **Schema 版本演进**：`output_schema_json` 变化时，可以自动检测旧版本产出的题目是否需要重新解析。
