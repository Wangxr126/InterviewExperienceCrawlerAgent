## 1. 范围

定义本项目的可观测性三大支柱：
- **日志（Logs）**：结构化 JSON + Loki 聚合
- **指标（Metrics）**：业务指标 + 系统指标 → Prometheus / Grafana
- **链路追踪（Traces）**：OTel SDK + Jaeger / Tempo（或 Langfuse）

---

## 2. trace_id 贯穿规范（已明确）

- Java 侧生成 trace_id，通过 HTTP Header（`X-Trace-Id`）和 RabbitMQ Message Header 传递。
- Python Worker 接收 trace_id 后注入到所有日志和子调用。
- LLM 调用 / Neo4j 调用 / MySQL 调用 都带 trace_id。
- AgentScope / LlamaIndex 通过 hooks/callback 自动落 trace_id。

---

## 3. 日志规范

| 字段 | 必填 | 说明 |
|---|---|---|
| `timestamp` | ✅ | ISO8601 |
| `level` | ✅ | DEBUG / INFO / WARN / ERROR |
| `service` | ✅ | 服务名 |
| `trace_id` | ✅ | 全链路 ID |
| `user_id` | ⚪ | 关联用户（如适用） |
| `event` | ✅ | 事件名（短字符串） |
| `message` | ⚪ | 自由文本 |
| `data` | ⚪ | 结构化字段（JSON） |

---

## 4. 指标命名规范

```
{domain}_{metric}_{unit}
例：
  crawl_tasks_total
  llm_call_latency_ms
  retrieval_recall_hit_rate
  sm2_review_completed_count
```
