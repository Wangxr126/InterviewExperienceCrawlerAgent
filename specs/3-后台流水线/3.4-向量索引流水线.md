## 1. 范围

本文档描述：**题目入库后，如何生成 embedding 并写入 Neo4j 向量索引**。包含：
- embedding 生成 worker 的触发与执行流程。
- 向量重算策略。
- MySQL `question_vectors` 派生层的维护。

不包含：
- 向量索引的 schema 定义（见 [2.3](../2-数据模型/2.3-Neo4j图谱Schema.md) §3.2）。
- 向量召回查询逻辑（见 [4.2 GraphRAG 查询模式](../4-检索召回/4.2-GraphRAG查询模式.md)）。

---

## 2. 总体流程

```
题目入库（MySQL questions + Neo4j Question 节点）
        │
        ▼ （RabbitMQ 异步）
[向量构建 Worker]
        │
        ├─ ① 读取题干 + 必要上下文（如 tags）
        ├─ ② 调用 embedding 模型
        ├─ ③ 写入 Neo4j Question.embedding
        └─ ④ 写入 MySQL question_vectors（派生层，记录 model/hash/payload）
```

---

## 3. 触发条件

| 触发场景 | 触发方 | 说明 |
|---|---|---|
| 新题入库 | Java 写 `questions` 后发 MQ | 一次性向量构建 |
| 题干被修正 | Java 检测到 `question_text` 变更 | 重算 |
| Embedding 模型升级 | 运维触发批量重算 | 全库重建 |
| 向量缺失补救 | 定时扫描 `question_vectors` 缺失或 `source_text_hash` 不匹配 | 增量补 |

## 4. 队列配置

| 队列 | 生产方 | 消费方 | DLQ |
|---|---|---|---|
| `vector.build.queue` | Java（题目入库后）/ 定时扫描器 | `vector-build-worker` | `vector.build.dlq` |

---

## 5. 服务清单

| 服务名 | 语言 | 部署单元 | 核心职责 |
|---|---|---|---|
| `vector-build-worker` | Python | 独立 Worker 进程 | 消费 `vector.build.queue`，调用 embedding，写 Neo4j + MySQL |
| `vector-rebuild-job` | Python | 定时任务 | 扫描需要重建的向量 |

---

## 6. 向量层和事实层的边界

| 层 | 责任 |
|---|---|
| `questions` | 维护题库事实和当前快照 |
| Neo4j `Question.embedding` | 真正参与检索的向量 |
| MySQL `question_vectors` | 派生层，记录向量元数据（模型/维度/hash/payload） |

向量层不是事实源，因此：
- 可以重建（删了重跑即可）。
- 可以与主表适度重复过滤字段（`company`、`position`、`difficulty` 等放进 `payload_json`）。
- 不要把版本历史、用户态或流程中间态塞进去。

## 7. Embedding 模型选型

| 维度 | 当前规划 | 备选 |
|---|---|---|
| 提供商 | OpenAI `text-embedding-3-small`（1536 维） | BGE-M3、Jina、本地部署 |
| 维度 | 1536 | 较大模型可达 3072 |
| 成本 | 每 1M tokens 约 $0.02 | 自部署可降至 0 但需 GPU |

## 8. 性能与成本控制

| 措施 | 说明 |
|---|---|
| 批量调用 | 一次请求 100 个题，节省网络开销 |
| 增量去重 | 已生成相同 `source_text_hash` 的不重复调用 |
| 重试退避 | 限流 / 超时按指数退避 |
| 成本统计 | 写入 [7.1 可观测性](../7-运维与可观测/7.1-可观测性设计.md) 中的 LLM 调用审计表 |
