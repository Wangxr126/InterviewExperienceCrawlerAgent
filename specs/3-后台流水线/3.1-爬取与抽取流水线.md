## 2. 链接来源三种类型

链接进入系统的方式有三种，在 `source_links.submit_type` 字段区分：

| 类型 | submit_type | 触发方 | 说明 |
|---|---|---|---|
| **手动输入** | `manual` | 用户 | 在界面粘贴单条或多条 URL，排队正常处理 |
| **立即爬取** | `immediate` | 用户 | 用户明确要求现在就爬，高优先级插队 |
| **定时发现** | `scheduled` | 系统 | 定时任务爬取列表页，自动发现新帖 URL |

三种类型进入 `source_links` 后，后续的爬取→抽取流程**完全相同**，仅 `crawl_tasks.priority` 有差异（immediate = high）。

## 3. 语言分工总览

> Python 在爬虫工具链上积累丰富（Playwright / BeautifulSoup / httpx / Scrapy），爬取相关逻辑全部由 Python 承担；Java 负责调度、状态管理、API 接入。

| 模块 | 语言 | 工具 / 框架 | 职责 |
|---|---|---|---|
| URL 提交 API | **Java** | Spring Boot | 接收手动/立即提交的 URL，写 source_links，发 MQ |
| 定时调度 | **Java** | Spring Scheduler | 按 cron 触发链接发现任务，发 MQ |
| **链接发现 Worker** | **Python** | Playwright / BeautifulSoup | 爬列表页，解析出新帖 URL，写 source_links |
| **页面爬取 Worker** | **Python** | Playwright / httpx + BeautifulSoup | 爬帖子正文，清洗为纯文本，写 crawl_artifacts |
| 爬取完成→触发抽取 | **Java** | Spring Boot（监听/轮询） | crawl_tasks 成功后生成 extraction 任务，发 MQ |
| **LLM 抽取 Worker** | **Python** | LlamaIndex + LLM SDK | 消费 extraction.queue，调用 LLM，写 extracted_question_items |
| 审核入库 API | **Java** | Spring Boot | Playground 审核后写入 questions 表 |

## 5. 三种来源的入口流程

### 5.1 手动输入（manual）

**责任方**：Java API

```
用户在前端粘贴 URL 列表 → POST /api/links/submit
    │
    ▼
Java: normalize + 去重写入 source_links（submit_type=manual）
    │
    ▼
Java: 写 crawl_tasks（priority=normal）→ 发布到 crawl.queue
```

### 5.2 立即爬取（immediate）

**责任方**：Java API

```
用户点击"立即爬取"按钮 → POST /api/links/submit?immediate=true
    │
    ▼
Java: normalize + 去重写入 source_links（submit_type=immediate）
    │
    ▼
Java: 写 crawl_tasks（priority=high）→ 发布到 crawl.queue（高优先级消息）
```

> **TODO**：RabbitMQ 消息优先级队列配置（`x-max-priority`）待实现阶段确定，或用独立 `crawl.high.queue` 实现优先级隔离。

### 5.3 定时发现（scheduled）

**责任方**：Java（调度触发）+ Python（链接发现 Worker）

```
Java Spring Scheduler 按 cron_expr 触发
    │
    ▼
读取 crawl_seeds（is_active=1）→ 发布到 link.discovery.queue
    │
    ▼
Python link-discovery-worker 消费：
    │  用 Playwright / BeautifulSoup 爬列表页（max_pages 页）
    │  解析出帖子 URL 列表
    │  过滤：去掉已存在于 source_links 的 URL
    │
    ▼
写入 source_links（submit_type=scheduled，seed_id=...）
    │
    ▼
Java 生成 crawl_tasks（priority=normal）→ 发布到 crawl.queue
    │  （同手动流程，后续完全一致）
    ▼
更新 crawl_seeds.last_run_at，last_found_count
```

## 6. 后续共同流程（三种来源一致）

### 6.1 页面爬取 Worker（Python）

**消费**：`crawl.queue`  
**工具**：httpx（静态页）/ Playwright（JS 渲染页）+ BeautifulSoup（解析）  
**写入**：`crawl_artifacts.parsed_text`，更新 `crawl_tasks.status`

```python
def handle(message):
    task = get_task(message.task_id)
    if task.status != 'pending': return  # 幂等

    set_status(task, 'in_progress')
    try:
        raw_html    = fetch_page(task.url)       # TODO: 各平台 JS 渲染判断策略待定
        parsed_text = parse_and_clean(raw_html)  # 提取正文，去掉导航/广告/评论
        insert_crawl_artifact(task.task_id, task.source_link_id, parsed_text)
        set_status(task, 'success')
        ack(message)
    except Exception as e:
        set_error(task, e)
        nack(message)
```

**失败类型**：

| 类型 | 处理 |
|---|---|
| 网络超时 / 5xx | nack → 重投，指数退避。TODO: 重试次数待定 |
| 403 / 反爬 | 标记 `blocked`，暂停该域名，人工处理 |
| 解析后空文本 | 标记 `parse_failed`，不重试，人工检查平台解析规则 |

> **TODO**：牛客 / 掘金 / 知乎各平台正文选择器及 JS 渲染判断逻辑，待实现时按平台维护配置。

### 6.3 LLM 抽取 Worker（Python + LlamaIndex）

**消费**：`extraction.queue`  
**写入**：`extracted_question_items`，更新 `question_extraction_runs.status`

```python
def handle(message):
    run = get_run(message.run_id)
    if run.status != 'pending': return  # 幂等

    set_status(run, 'in_progress')
    try:
        text   = get_artifact(run.artifact_id).parsed_text
        prompt = get_prompt_version(run.prompt_version_id)
        result = call_llm(prompt, text)
        items  = parse_json_output(result)   # 按 output_schema 解析

        for item in items:
            insert_extracted_question_item(run.run_id, item)

        set_status(run, 'success', item_count=len(items))
        ack(message)
    except Exception as e:
        set_error(run, e)
        nack(message)
```

**LLM 输出 JSON Schema**（由 `prompt_versions` 管理）：

```json
{
  "type": "array",
  "items": {
    "required": ["question_text"],
    "properties": {
      "question_text": { "type": "string" },
      "answer_text":   { "type": "string" },
      "difficulty":    { "type": "string", "enum": ["easy", "medium", "hard"] },
      "tags":          { "type": "array", "items": { "type": "string" } },
      "company":       { "type": "string" },
      "position":      { "type": "string" }
    }
  }
}
```

**失败类型**：

| 类型 | 处理 |
|---|---|
| LLM 超时 / 限流 | nack → 重投。TODO: 退避策略待定 |
| JSON 解析失败 | 重试一次；再失败标记 `parse_failed`（prompt 问题） |
| Token 超长 | 截断后重试。TODO: 截断策略（按段落/字符数）待定 |

## 7. 任务状态流转

### `crawl_tasks.status`
```
pending → in_progress → success
                     ↘ retrying → (success | failed)
                     ↘ failed
                     ↘ blocked       （反爬，人工处理）
                     ↘ parse_failed  （正文为空，调整解析规则）
```

### `question_extraction_runs.status`
```
pending → in_progress → success
                     ↘ retrying → (success | failed)
                     ↘ failed
                     ↘ parse_failed  （LLM 输出格式持续错误）
```

## 9. 服务清单

| 服务名 | 语言 | 部署单元 | 核心职责 |
|---|---|---|---|
| `api-service` | Java | Spring Boot 应用 | URL 提交 API、触发抽取、审核入库 API |
| `scheduler-service` | Java | 与 api-service 合并或独立 | Spring Scheduler 触发定时发现任务 |
| `link-discovery-worker` | Python | 独立 Worker 进程 | 爬列表页，发现新帖 URL，写 source_links |
| `crawl-worker` | Python | 独立 Worker 进程 | 爬帖子正文，写 crawl_artifacts |
| `extraction-worker` | Python + LlamaIndex | 独立 Worker 进程 | LLM 抽取，写 extracted_question_items |

| 里程碑 | 内容 |

| M1 | 手动 / 立即提交 URL → crawl-worker → crawl_artifacts |
