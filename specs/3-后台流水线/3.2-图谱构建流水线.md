## 1. 范围

本文档描述：**题目入库后，如何把题目和知识概念之间的关系写入 Neo4j**。包含：
- 概念去重与节点创建。
- BELONGS_TO 层级建立。
- COVERS_CONCEPT 关系建立。
- RELATED_TO 自动推断（多路来源）。

不包含：
- 节点和关系定义（见 [2.3](../2-数据模型/2.3-Neo4j图谱Schema.md)）。
- 向量索引构建（见 [3.4](3.4-向量索引流水线.md)）。
- 图谱质量监控与人工审核（见 [8.1](../8-治理与质量/8.1-图谱健康治理.md)）。

---

## 2. 总体流程

```
题目抽取（LLM 调用，同步）
        │
        │ 输出：question_text, answer_text, tags_json,
        │       concepts: [{name, parent_hint, description}]
        ▼
题目入库 → MySQL questions 表 + Neo4j Question 节点
        │
        ▼ （RabbitMQ 异步，不阻塞入库）
[概念建图 Worker]
        │
        ├─ ① 概念去重（向量相似检索）
        ├─ ② 概念节点创建或复用
        ├─ ③ BELONGS_TO 关系建立
        ├─ ④ COVERS_CONCEPT 关系建立
        └─ ⑤ RELATED_TO 初步推断（小问 LLM）
```

---

## 3. 步骤 1 — LLM 同步提取概念（与题目一起提取）

在 `question_extraction_runs` 的 prompt 里，要求 LLM 同时输出：

```json
{
  "questions": [
    {
      "question_text": "...",
      "answer_text": "...",
      "tags": ["Spring", "Java"],
      "company": "...",
      "position": "...",
      "difficulty": "...",
      "question_type": "...",
      "concepts": [
        {
          "name": "IOC",
          "parent_hint": "Spring",
          "description": "控制反转，Spring 容器管理 Bean 生命周期的核心机制",
          "confidence": 0.95
        },
        {
          "name": "BeanFactory",
          "parent_hint": "IOC",
          "description": "Spring IOC 容器的底层接口",
          "confidence": 0.85
        }
      ]
    }
  ]
}
```

`parent_hint` 是 LLM 对"父概念叫什么"的猜测，后续建图 Worker 用它来匹配已有节点。

---

## 4. 步骤 2 — 概念去重（向量相似检索 + 小问 LLM）

```
对新概念 "IOC"：

① 用 "IOC" 的 embedding 在 Neo4j Concept 节点里做相似检索，取 top-5
   → 结果：["控制反转(0.96)", "依赖注入(0.82)", "Spring 容器(0.74)", ...]

② 相似度 ≥ 0.92 的候选 → 小问 LLM（极短 prompt）：
   "请问 'IOC' 和 '控制反转' 是否指同一个概念？只回答 yes/no。"
   → yes → 复用已有节点 "控制反转"，不新建

③ 相似度 < 0.92 且 top-1 相似度 < 0.75 → 新建 Concept 节点 "IOC"
```

**Token 消耗说明**：

- 步骤 ② 的 prompt 极短（< 50 tokens），成本可忽略。
- 全量概念列表**从不**传给 LLM，只传相似度排前 5 的候选。

---

## 5. 步骤 3 — BELONGS_TO 层级建立

```
用 parent_hint（如 "Spring"）做节点匹配：
1. 先精确匹配已有节点名称
2. 无精确匹配 → 向量搜索，取最相似的已有节点（阈值 > 0.85）
3. 仍无匹配 → 挂在 parent_hint 对应 Domain 下（如匹配不到 Spring，则挂到 Java）
4. 最终兜底 → 挂到 "未分类" 根节点，标记待人工审核
```

人工审核入口见 [8.1 图谱健康治理](../8-治理与质量/8.1-图谱健康治理.md)。

---

## 6. 步骤 4 — COVERS_CONCEPT 关系

每道题目的每个概念建立 `(Question)-[:COVERS_CONCEPT {confidence}]->(Concept)` 关系。

---

## 7. 步骤 5 — RELATED_TO 初步推断

对新建的概念节点，触发一次**极短的 LLM 调用**：

```
输入：当前概念 "IOC"，以及它的相邻概念（兄弟节点 + 父节点子节点，最多 10 个）
问题："IOC 和以下哪些概念有重要关联？列出最多 3 个，并说明关系类型。"
候选：["AOP", "DI", "BeanFactory", "ApplicationContext", "Spring Boot", ...]
```

输出：建立 `RELATED_TO` 关系，`source = "llm_inferred"`。

---

## 8. RELATED_TO 的三路来源

### 8.1 A 路 — 手动种子图

在顶级 Domain 节点间预建骨架关系，如：

- `(MySQL)-[:RELATED_TO {relation_type:"sibling"}]-(Redis)` （同属数据库领域）
- `(微服务)-[:RELATED_TO {relation_type:"complement"}]-(Docker)`

### 8.2 B 路 — LLM 推断（入库时）

见 §7，对每个新概念，结合局部邻居推断关系。

### 8.3 C 路 — 共现挖掘（定时批量）

```cypher
-- 统计：哪些概念对总出现在同一道题里
MATCH (c1:Concept)<-[:COVERS_CONCEPT]-(q:Question)-[:COVERS_CONCEPT]->(c2:Concept)
WHERE c1 <> c2 AND id(c1) < id(c2)
WITH c1, c2, count(q) AS cooccurrence
WHERE cooccurrence >= 10   -- 共现超过 10 次
RETURN c1.name, c2.name, cooccurrence
ORDER BY cooccurrence DESC
```

共现超过阈值的概念对 → 写入 `RELATED_TO {relation_type: "cooccurrence", weight: cooccurrence}`。

## 11. 里程碑

| 里程碑 | 内容 | 完成标志 |
|---|---|---|
| M1 | 手动建 Domain 种子节点（~30 个） | Domain 节点全部入 Neo4j |
| M2 | 题目抽取 prompt 加入概念提取 schema | 新题入库时自动产出 concepts |
| M3 | 概念建图 Worker 上线（去重 + BELONGS_TO + COVERS_CONCEPT） | 每道入库题都有 Concept 节点关联 |
| M4 | RELATED_TO 自动建立（LLM 推断 + 共现挖掘） | 概念间有合理的横向关系 |
