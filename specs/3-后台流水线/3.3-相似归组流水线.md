# 3.3 - 相似归组流水线

更新时间：2026-05-09  
关联文档：[2.5 相似归组表](../2-数据模型/2.5-相似归组表.md)、[2.3 Neo4j 图谱 Schema](../2-数据模型/2.3-Neo4j图谱Schema.md)、[3.2 图谱构建流水线](3.2-图谱构建流水线.md)、[3.4 向量索引流水线](3.4-向量索引流水线.md)、[8.2 相似归组人工审核](../8-治理与质量/8.2-相似归组人工审核.md)

> **重要边界：本文档只涉及题库浏览展示层的相似归组，不影响任何入库流程。**

---

## 1. 问题定义

### 1.1 当前状态

- **入库层面**：唯一的去重维度是帖子 URL（`source_links.url` 唯一约束）。同一道题从不同帖子被抽取进来，会产生多条 `questions` 记录——**这是正常现象，入库链路不做任何改变**。
- **展示层面**：浏览题库时，用户看到的是所有原始题目，包括大量"同一道题的不同说法"，体验差。

### 1.2 要解决的问题

**只在浏览展示时**，把语义相近的题目折叠起来，只展示一道代表题；用户可以展开看所有变体。

**不改变的事**：
- 题目入库流程不变，所有题继续正常写入 `questions` 表。
- 不在入库时做相似性判断。
- 不删除任何已入库的题目。

### 1.3 两个场景对比

| 场景 | 需求 | 处理方式 |
|---|---|---|
| **题库浏览** | 不想看到"一堆不同说法的同一道题" | 折叠变体，只展示代表题 |
| **题目详情页** | 想看"这道题还有哪些问法" | 展开同组所有变体 |

---

## 2. 分层设计总览

```
Layer 1：URL 去重         → 入库时，source_links.url 唯一约束（已有，不动）
                                        ↓ 所有题正常入库
Layer 2：GraphRAG 相似归组 → 入库后，后台异步任务运行，产出"归组关系"
                                        ↓ 只影响展示
Layer 3：展示层折叠        → 浏览 API 查询时，用归组结果过滤（MySQL 侧过滤）
```

Layer 1 和 Layer 2 **完全解耦**，归组任务在入库完成之后异步运行，不阻塞任何写入。

## 3. GraphRAG 归组的核心思路

### 3.1 为什么用 GraphRAG 而不是纯向量相似

纯向量相似度只看"文字像不像"，会漏掉大量"说法不同但考察同一知识点"的题目：

| 题目 A | 题目 B | 向量相似 | 实质 |
|---|---|---|---|
| "什么是 IOC？" | "Spring 容器怎么工作？" | 0.62（低） | 同一知识点 |
| "MySQL 索引失效的原因" | "什么情况下走不了索引？" | 0.68（中） | 同一个问题 |
| "讲一下单例模式" | "手写线程安全的单例" | 0.55（低） | 高度相关，不同角度 |

GraphRAG 利用知识图谱的**结构信息**（题目连接到哪些 Concept、Tag 节点）来补充向量的不足：

```
"什么是 IOC？"  ─── COVERS_CONCEPT ───► [IOC]  ◄─── COVERS_CONCEPT ─── "Spring 容器怎么工作？"
                 ─── COVERS_CONCEPT ───► [Spring]◄─── COVERS_CONCEPT ──┘

两题共享 2 个概念节点 → 是归组候选
```

### 3.2 综合相似评分

对任意两道题 A、B：

```
score(A, B) =
    α × vector_sim(A, B)        // 文本向量相似（embedding cosine）
  + β × concept_jaccard(A, B)   // 共享知识概念的 Jaccard
  + γ × tag_jaccard(A, B)       // 共享标签的 Jaccard
  + δ × context_bonus(A, B)     // 同公司同岗位的结构加分
```

默认权重（可调）：α=0.50, β=0.25, γ=0.15, δ=0.10。

### 3.3 候选对生成（双路召回）

不对所有题两两比较（O(n²)），而是双路产生候选对：

**向量路**：对每道题做 embedding 向量检索，取 top-20 最近邻题目。

**图谱路**：在 Neo4j 中找"共享 Concept 节点的其他 Question 节点"。

```cypher
MATCH (q1:Question {id: $q_id})-[:COVERS_CONCEPT]->(c:Concept)<-[:COVERS_CONCEPT]-(q2:Question)
WHERE q1 <> q2
RETURN q2.id AS candidate_id, count(c) AS shared_concepts
ORDER BY shared_concepts DESC LIMIT 20
```

两路候选合并去重，计算综合评分，按阈值决定处理方式。

### 3.4 阈值策略

| 综合分 | 处理 |
|---|---|
| ≥ 0.88 | **自动归组**：直接记为同一组，A 是 B 的变体题 |
| 0.72 ~ 0.88 | **人工审核**：进审核队列，人工确认是否归组（详见 [8.2](../8-治理与质量/8.2-相似归组人工审核.md)） |
| 0.55 ~ 0.72 | **相关题**：不归组，但作为"相关题推荐"的信号（写 Neo4j `RELATED_TO`） |
| < 0.55 | 不相关，忽略 |

## 5. Neo4j 关键查询

**查一道题的所有变体（详情页展开用）**：
```cypher
MATCH (q:Question {id: $q_id})-[:VARIANT_OF*1..2]-(variant:Question)
RETURN variant
```

**GraphRAG 问答扩展：从一道题展开相关知识体系**：
```cypher
MATCH (q:Question {id: $q_id})
OPTIONAL MATCH (q)-[:VARIANT_OF*1..2]-(variant)
OPTIONAL MATCH (q)-[:COVERS_CONCEPT]->(c:Concept)-[:RELATED_TO*1..2]-(rc:Concept)
OPTIONAL MATCH (rc)<-[:COVERS_CONCEPT]-(related_q:Question)
RETURN q,
       collect(DISTINCT variant)   AS variants,
       collect(DISTINCT related_q) AS related_questions,
       collect(DISTINCT rc)        AS related_concepts
```

更多查询模式详见 [4.2 GraphRAG 查询模式](../4-检索召回/4.2-GraphRAG查询模式.md)。

## 6. 后台归组任务

归组不在入库路径上执行，而是作为独立的后台任务异步运行：

```
[入库完成]  →  MySQL questions 表新增记录，dedup_status = 'unprocessed'
                        │
                        ▼ (后台任务，不阻塞入库)
              [归组 Worker 轮询 unprocessed 的题目]
                        │
                        ▼
              ① 文本指纹检查（快速）
                        │
              ② 双路候选召回（向量路 + 图谱路）
                        │
              ③ 综合评分
                        │
              ④ 按阈值写入结果：
                   ≥ 0.88     → 写 VARIANT_OF + MySQL 归组表
                   0.72~0.88  → 写 dedup_review_queue
                   0.55~0.72  → 写 Neo4j RELATED_TO
                   < 0.55     → dedup_status = 'no_match'
```

触发方式：
- **定时触发**：每天跑一次，处理所有 `unprocessed` 的题目。
- **手动触发**：后台管理页可以对指定题目或全库重新跑归组。

## 7. 代表题选取规则

组内多道题时，自动按以下优先级选代表题（人工可覆盖）：

1. 有人工修正记录的题（答案更可靠）。
2. `answer_text` 最长的题（内容更完整）。
3. `source_platform` 评级较高的平台来源。
4. `composite_score` 最高的题（最接近组中心）。
5. `created_at` 最早的题（最先入库）。

## 8. 场景化展示行为

| 场景 | 展示规则 | 数据来源 |
|---|---|---|
| **题库浏览 / 搜索** | 每组只展示代表题，变体折叠 | MySQL：`is_group_representative = 1 OR duplicate_group_id IS NULL` |
| **题目详情页 → 变体题** | 展示同组所有变体题及相似分 | Neo4j：`MATCH (q)-[:VARIANT_OF*1..2]-(v)` |
| **题目详情页 → 相关题** | 展示相关但不同的题 | Neo4j：沿 `RELATED_TO` + `COVERS_CONCEPT` 扩展 |
| **练习 / 刷题** | 同组只出一道，做过后排除整组 | 排除同 `duplicate_group_id` 的已做题 |
| **模拟面试出题** | 同组只出代表题，保证覆盖度 | `is_group_representative = 1` 优先 |
| **GraphRAG 问答** | 题目扩展到变体 + 相关题 + 相关概念 | Neo4j 多跳遍历 |
| **归组管理页（后台）** | 展示所有组、成员、相似分 | MySQL 管理表 |
