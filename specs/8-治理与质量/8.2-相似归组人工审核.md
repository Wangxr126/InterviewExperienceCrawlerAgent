## 1. 范围

本文档定义相似归组的**人工审核流程与界面**。算法层面（双路召回、阈值、综合评分）见 [3.3 相似归组流水线](../3-后台流水线/3.3-相似归组流水线.md)。

---

## 2. 进入审核队列的来源

| 来源 | 触发条件 | 写入表 |
|---|---|---|
| 自动归组流水线 | 综合分 0.72 ~ 0.88 | `dedup_review_queue` |
| 用户在题库页"举报"两道题应为同一题 | 用户点击"我觉得这两题相同" | `dedup_review_queue`（review_method = `user_report`） |
| 后台批量重跑 | 管理员触发"全库重新归组" | `dedup_review_queue` |

---

## 3. 前端功能点

### 3.1 归组管理页（B7）

| 功能 | 说明 |
|---|---|
| 组列表 | 组大小、代表题预览、归组方式 |
| 组详情 | 成员列表、综合分、共享概念/标签 |
| 切换代表题 | 手动指定代表题 |
| 合并两个组 | 把两个独立组合并为一个 |
| 拆分组 | 把某道题从组内移除 |
| 手动建组 | 搜索两道题，手动标记为同组 |

### 3.2 审核队列页（B8）

| 功能 | 说明 |
|---|---|
| 待审核列表 | 按综合分从高到低展示题目对 |
| 并排展示 | 两道题左右对比，展示共享概念和标签名称 |
| 快速操作 | "归为同组" / "不同题" / "忽略" |
| 批量操作 | 选中多对 → 批量"忽略" |

---

## 4. 审核结果回写

| 用户操作 | 数据动作 |
|---|---|
| 归为同组 | `dedup_review_queue.review_status = 'same_group'`；写 `question_group_members`；写 Neo4j `VARIANT_OF` |
| 不同题 | `review_status = 'different'`；不写归组关系；可选写 `RELATED_TO`（如果共享概念较多） |
| 忽略 | `review_status = 'ignored'`；不再进入队列 |

---

## 5. 审核质量保证

- **审核记录留档**：所有审核动作记录 `reviewer_user_id`、`reviewed_at`、`review_note`，便于回溯。
- **审核员准则文档**：维护一份"什么算同一题"的判定标准，置于本文档附录或单独维护。
- **冲突处理**：如果用户举报与系统判断冲突，进入二次复核。

---

## 6. 审核成本控制

- **优先级排序**：综合分越接近 0.88 的优先审核，越接近 0.72 的可以延后。
- **批量忽略**：明显不相关的题对（共享概念 < 1）支持批量忽略。
- **自动收敛**：积累审核样本后，可调整阈值（例如发现 0.85 以上几乎都被判同组，可降低自动归组下限到 0.85）。

---

## 7. 后续扩展

- **审核标注作为训练数据**：积累 1000+ 样本后，可用于训练二分类小模型（"是否同组"）。
- **主动学习**：不只看综合分高低，还看模型不确定性，优先审核"模型纠结"的样本。
- **群体归组**：当前只判断两两关系，后续可以做"一组 N 题"的整体审核。
