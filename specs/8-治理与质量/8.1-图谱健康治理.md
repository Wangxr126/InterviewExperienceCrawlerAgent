## 1. 范围

本文档覆盖知识图谱（Neo4j Concept / Domain / Question 网络）的：
- 质量保证策略（如何防止图谱污染）。
- 健康监控指标（如何衡量图谱状态）。
- 人工审核入口与流程。

不包含图谱的写入流水线（见 [3.2](../3-后台流水线/3.2-图谱构建流水线.md)）。

---

## 2. 六层质量保证策略

| 层次 | 策略 | 触发时机 | LLM 成本 |
|---|---|---|---|
| **L1 入库时去重** | 新概念 embedding 相似搜索，> 0.92 复用已有节点 | 每次概念入库 | 极低（只有 embedding） |
| **L2 模糊判断** | top-5 候选，小问 LLM "是否同一概念" | 相似度 0.80~0.92 时 | 很低（< 50 tokens/次） |
| **L3 共现挖掘** | 题目共现批量统计，超阈值自动建 `RELATED_TO` | 每周定时任务 | 零 |
| **L4 结构健康检查** | 孤立节点、游离概念（无 BELONGS_TO）、度异常节点 | 每周定时任务 | 零 |
| **L5 社区检测** | Louvain 算法找天然聚类，同簇高相似对 → 合并候选 | 每月一次 | 零（图算法） |
| **L6 批量 LLM 质检** | 每周取 50~100 个新概念，LLM 整体审查（重复、层级） | 每周一次 | 中等（一次批量调用） |

## 3. 图谱健康监控指标

```
每周自动计算并记录：
- 总节点数：Domain / Concept / Question / Tag / Company / Position
- 孤立概念比例（无任何题目 COVERS_CONCEPT 的 Concept）
- 无 BELONGS_TO 的游离概念数量
- 平均每道题覆盖的概念数（< 1 说明提取不足，> 10 说明提取过泛）
- RELATED_TO 密度（关系数 / 节点数²）
- VARIANT_OF 组的平均大小
```

这些指标在 [7.2 监控仪表盘](../7-运维与可观测/7.2-监控仪表盘.md) 中以图谱健康看板展示。

## 4. 人工审核入口

| 场景 | 进入审核队列的条件 |
|---|---|
| 概念去重 | 相似度 0.80~0.92，LLM 也无法判断 |
| 层级挂靠 | 父节点匹配失败，兜底挂到 "未分类" |
| 社区检测 | 检测到跨社区孤立节点 |
| 批量质检输出 | LLM 质检报告里标出的合并或分裂建议 |

审核结果写入 `concept_review_log` 表（MySQL，详见 [2.10 审计与检索事件表](../2-数据模型/2.10-审计与检索事件表.md)），保留每次决策记录。

---

## 5. 概念审核界面（B10）

| 功能 | 说明 |
|---|---|
| 待审节点列表 | 按 LLM 置信度排序 |
| 节点上下文展示 | 节点名 / 描述 / 相似候选 / 共享题目 |
| 决策动作 | 合并到已有节点 / 新建节点 / 改父节点 / 标记 deprecated / 跳过 |
| 批量操作 | 选择多节点批量合并 |
| 决策回写 | 写 `concept_review_log` + 更新 Neo4j |

---

## 6. 节点生命周期管理

| 状态 | 进入条件 | 出口 |
|---|---|---|
| `active` | 默认 | 任何节点 |
| `deprecated` | 人工标记 / 共现 = 0 持续 3 个月 | 召回不再使用，但保留历史关系 |
| `merged` | 被合并到其他节点 | 关系迁移到目标节点，原节点保留指向（链 ` MERGED_TO`） |

---

## 7. 周期任务清单

| 任务 | 频率 | 触发方 |
|---|---|---|
| 共现挖掘 | 每周一凌晨 | 定时 cron |
| 结构健康检查 | 每周一上午 | 定时 cron |
| LLM 批量质检 | 每周三 | 定时 cron |
| 社区检测（Louvain） | 每月一日 | 定时 cron |
| 健康指标导出 | 每天 | 定时 cron |
