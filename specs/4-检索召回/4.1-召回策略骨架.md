## 1. 召回总原则

题库召回不是单一算法，而是 "**意图识别 + 硬过滤 + 多路召回 + 去重融合 + 重排 + 多样性控制**" 的组合。

### 1.1 通用流程

| 步骤 | 作用 |
|---|---|
| 1. 意图识别 | 判断用户要搜索、练习、复习还是出题 |
| 2. 硬过滤 | 先用 company / position / difficulty / question_type / status 等字段收窄范围 |
| 3. 多路召回 | 同时走向量、标签、图谱、复习队列、关键词等多个来源 |
| 4. 候选融合 | 按 q_id 去重，保留来源列表和来源分数 |
| 5. 重排 | 用 reranker 或规则再排序 |
| 6. 多样性控制 | 控制同公司、同岗位、同标签的重复度 |
| 7. 反馈回写 | 更新薄弱标签、掌握度、相似归组、复习状态 |

### 1.2 通用设计原则

1. **先硬过滤，再向量召回。** 能用结构化字段先裁掉的，不要交给向量层兜底。
2. **向量层只负责语义相似，不负责事实真相。** 事实依旧在主表和关系表里。
3. **候选统一按 q_id 聚合。** 一个题可以来自多个来源，但最终只算一个候选。
4. **重排前先去重。** 避免同一题被不同来源反复进入 reranker。
5. **答案和用户态不参与主检索事实。** 用户状态放学习表，答案版本放版本层。
6. **召回结果要能解释。** 前端至少要知道"为什么推荐这道题"。

### 1.3 去重 vs 相似归组的边界

| 概念 | 发生时机 | 机制 | 存储字段 | 说明 |
|---|---|---|---|---|
| **帖子链接去重** | 采集链路入口 | `source_links.url` 唯一约束 | `source_links.url` | 防止同一帖子被重复爬取入库，是硬约束 |
| **题目相似归组** | 入库后或定期归组 | 向量相似度计算 + 阈值判断 | `questions.duplicate_group_id` | 把表述相近的题打上同一个 group，用于展示折叠；不删除题目，不是去重 |

详细机制见 [3.3 相似归组流水线](../3-后台流水线/3.3-相似归组流水线.md)。

## 2. 统一候选对象

无论哪一种召回场景，最终都返回统一结构的候选对象：

| 字段 | 来源 | 作用 |
|---|---|---|
| `q_id` | `questions.q_id` | 题目唯一标识 |
| `question_text` / `answer_text` | `questions` | 题干 / 答案快照 |
| `difficulty` / `question_type` | `questions` | 过滤与展示 |
| `company` / `position` / `business_line` | `questions` | 公司岗位推荐 |
| `tags` | `questions.tags_json` | 标签缓存 |
| `source_platform` / `source_url` | `questions` | 来源回链 |
| `duplicate_group_id` | `questions` | 折叠变体题 |
| `recall_source` / `recall_sources` | 召回层 | 主召回来源 / 全部召回来源 |
| `recall_score` | 召回层 | 聚合后的召回分 |
| `smart_type` | 召回层 | 智能练习时的类型 |
| `recommend_reason` | 召回层 | 推荐原因 |
| `next_review_at` | `user_question_progress` | 复习场景到期时间 |
| `concept_names` | Neo4j | GraphRAG 命中概念名 |

## 4. 智能混合练习策略要点

> 该场景没有独立子文档，要点在此沉淀，未来需要细化时拆分独立文档。

策略：
- 把到期复习、薄弱标签相似题、热门题、随机题分成多个召回源。
- 按权重融合候选。
- 融合后先去重（按 q_id 聚合），再重排。
- 最后控制题目类型和难度的分布。

建议：
- 这是最适合长期运行的一种模式。
- 题目来源要在结果里保留（`recall_sources`），方便前端展示"为什么推荐本题"。

---

## 5. 冷启动探索策略要点

策略：
- 热门题和基础题优先。
- 随机题保留一定比例。
- 不能全靠用户历史，因为新用户没有足够历史。
- 题型和难度要均衡分布。

建议：以覆盖面和稳定体验为主，不要太依赖个性化特征。

## 6. 融合与重排原则

### 6.1 候选融合

| 规则 | 说明 |
|---|---|
| 同一题去重 | 用 q_id 聚合候选 |
| 多源保留 | 保留 `recall_sources`，方便解释 |
| 多分数融合 | 不同来源可按权重叠加 |
| 来源上限 | 防止某一来源刷屏 |
| 相似归组过滤 | 同一 `duplicate_group_id` 的题，召回时只保留得分最高的一条（除非用户明确要看变体题） |

### 6.2 重排顺序建议

1. 是否满足硬过滤。
2. 是否属于目标场景的核心召回源。
3. 相似度或复习到期程度。
4. 多样性是否足够。
5. 是否与用户近期已做题过于接近。

### 6.3 结果解释

每道题最好带一个简短理由，对应 `recommend_reason` 字段，例如：
- 与你的薄弱标签相似。
- 属于到期复习题。
- 与目标公司 / 岗位高度匹配。
- 属于同知识点的扩展题。
- 属于随机均衡练习题。
