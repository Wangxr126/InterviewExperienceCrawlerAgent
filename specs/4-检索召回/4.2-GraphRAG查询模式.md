## 2. 召回架构：图谱主路 + Neo4j 向量兜底

**图谱路是主路，向量路是兜底，两路都在 Neo4j 内完成，不引入独立向量数据库。**

| 路径 | 触发条件 | 机制 |
|---|---|---|
| **图谱主路** | query 能提取到 Concept 节点 | 沿 COVERS_CONCEPT + RELATED_TO 扩展 |
| **向量兜底** | 图谱路结果不足，或无法提取 Concept 节点 | Neo4j 内置 vector index 相似搜索 |

图谱路优先的原因：
- 图谱路理解 "IOC" 和 "控制反转" 是同一知识点，向量路不稳定。
- 图谱路结果天然可解释（命中了哪些概念节点）。
- 向量路适合兜底：新题尚未建图，或极生僻技术词。

Neo4j 5.x 内置向量索引，两路可在同一系统完成，无需 Qdrant。

## 3. 完整召回流程

```
用户 query
      │
      ▼
① 实体提取（小 LLM 调用或关键词匹配）
      │ → 提取 query 对应的 Concept 名称
      │
      ├─ 提取成功 ──→ 图谱主路（Neo4j Cypher 遍历）
      │                  COVERS_CONCEPT + RELATED_TO 扩展
      │                  → 候选题目 + 概念路径（可解释）
      │
      └─ 提取失败 ──→ 向量兜底（Neo4j vector index）
         或结果 < 5       query embedding 相似搜索
                          → 候选题目 + 相似分
      │
      ▼
② 候选融合（按 q_id 去重，保留来源路径）
      │
      ▼
③ 重排（reranker 或规则）
      │
      ▼
④ 上下文组装 → LLM 回答
```

## 4. 核心查询模式

### 4.1 题目详情页 — 相关题召回

```cypher
// 从一道题出发，找覆盖相同概念的其他题
MATCH (q:Question {id: $q_id})-[:COVERS_CONCEPT]->(c:Concept)<-[:COVERS_CONCEPT]-(related:Question)
WHERE q <> related AND related.status = 'active'
WITH related, count(c) AS shared_concepts, collect(c.name) AS concept_names
ORDER BY shared_concepts DESC
LIMIT 10
RETURN related, shared_concepts, concept_names
```

### 4.2 题目详情页 — 知识体系扩展（相关概念）

```cypher
// 从题目的概念出发，沿 RELATED_TO 扩展一跳，找相关概念及对应题目
MATCH (q:Question {id: $q_id})-[:COVERS_CONCEPT]->(c:Concept)
-[:RELATED_TO*1..2]-(related_c:Concept)
<-[:COVERS_CONCEPT]-(related_q:Question)
WHERE q <> related_q AND related_q.status = 'active'
RETURN DISTINCT related_q, related_c
LIMIT 10
```

### 4.3 模拟面试出题 — 按概念覆盖出题

```cypher
// 给定岗位，找核心概念，再按概念选题（保证覆盖度）
MATCH (pos:Position {name: $position})<-[:FOR_POSITION]-(q:Question)
-[:COVERS_CONCEPT]->(c:Concept)-[:BELONGS_TO*1..3]->(d:Domain)
WHERE q.status = 'active'
WITH d.name AS domain, c.name AS concept, collect(q) AS questions
RETURN domain, concept, questions
ORDER BY domain, concept
```

### 4.4 标签 / 知识点练习 — 概念向上扩展

```cypher
// 用户选择了 "IOC"，向上找父节点，向下找子节点，拿到完整概念族
MATCH (target:Concept {name: $concept_name})
OPTIONAL MATCH (target)-[:BELONGS_TO*1..2]->(parent)
OPTIONAL MATCH (child)-[:BELONGS_TO*1..2]->(target)
OPTIONAL MATCH (related)-[:RELATED_TO]-(target)
WITH collect(DISTINCT target) + collect(DISTINCT parent)
   + collect(DISTINCT child) + collect(DISTINCT related) AS concept_pool
UNWIND concept_pool AS c
MATCH (q:Question)-[:COVERS_CONCEPT]->(c)
WHERE q.status = 'active'
RETURN DISTINCT q
LIMIT 30
```

### 4.5 智能问答（RAG 增强上下文）

```cypher
// 给定用户 query 匹配到的核心概念，扩展上下文
MATCH (c:Concept {name: $matched_concept})
OPTIONAL MATCH (c)-[:RELATED_TO*1..1]-(related_c:Concept)
OPTIONAL MATCH (q:Question)-[:COVERS_CONCEPT]->(c)
WHERE q.status = 'active'
WITH c, collect(DISTINCT related_c)[..5] AS related_concepts,
     collect(DISTINCT q)[..5] AS questions
RETURN c, related_concepts, questions
```

### 4.6 相似归组候选召回（图谱路）

```cypher
// 找共享概念的候选题（双路召回的图谱路）
MATCH (new_q:Question {id: $new_q_id})-[:COVERS_CONCEPT]->(c:Concept)
<-[:COVERS_CONCEPT]-(candidate:Question)
WHERE new_q <> candidate AND candidate.status = 'active'
WITH candidate, count(c) AS shared_concepts
WHERE shared_concepts >= 2
RETURN candidate.id AS candidate_id, shared_concepts
ORDER BY shared_concepts DESC
LIMIT 20
```

### 4.7 向量兜底查询

```cypher
// 当无法匹配 Concept 时
CALL db.index.vector.queryNodes('question-embeddings', 20, $query_embedding)
YIELD node AS q, score
WHERE q.status = 'active'
RETURN q, score
```

### 4.8 薄弱域补题（学习场景）

```cypher
// 薄弱概念：MySQL 事务
MATCH (c:Concept {name: 'MySQL 事务'})-[:RELATED_TO*1..2]-(c2:Concept)
<-[:COVERS_CONCEPT]-(q:Question)
WHERE q.status = 'active'
RETURN q.q_id, q.question_text
LIMIT 5
```

## 5. 与 LlamaIndex 集成

### 5.1 LlamaIndex 组件分工

| LlamaIndex 组件 | 职责 |
|---|---|
| `Neo4jGraphStore` | 图谱连接层，执行 Cypher |
| `KnowledgeGraphIndex` | 基于图谱的检索索引（主路） |
| `VectorStoreIndex`（Neo4j backend） | 向量索引（兜底路，同在 Neo4j 内） |
| `RouterQueryEngine` | 根据是否提取到 Concept 节点，路由到主路或兜底路 |
| `QueryEngine` | 组合两路结果，产出最终上下文 |

### 5.2 Callback 与可观测

利用 LlamaIndex Callback Manager，把每次 query 的子步骤（retrieve / rerank / synthesize）落到 [2.10 审计与检索事件表](../2-数据模型/2.10-审计与检索事件表.md) 中的 `retrieval_event`，便于回放和评估。

## 6. 性能注意事项

| 场景 | 注意点 |
|---|---|
| `RELATED_TO*1..2` | 跳数限制不要超过 2，否则候选爆炸 |
| `COVERS_CONCEPT` 反向遍历 | 高频概念（如 "Java"）反向题目数巨大，需 LIMIT |
| 向量索引查询 | 一次查询 top-K 控制在 ≤ 50，避免 Neo4j 计算压力 |
| 大型 Domain 子树 | 用 `BELONGS_TO*1..3` 限定深度 |
