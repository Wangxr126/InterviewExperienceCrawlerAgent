# 2.10 - 审计与检索事件表

更新时间：2026-05-09

## 1. 表清单

| 表名 | 职责 |
|---|---|
| `retrieval_event` | 检索召回审计（query → 候选 → 重排 → 输出） |
| `concept_review_log` | 概念审核记录（图谱治理决策） |
| `llm_call_audit` | LLM 调用审计（token / 费用 / 延迟 / 模型版本） |

> 这些表都是"附属审计层"，不在业务主链路上，可重建。但写入路径必须高效（异步 / 批量），不能拖慢主请求。

---

## 2. `retrieval_event`

LlamaIndex Callback Manager 钩子在每次召回完成后落一行（或多行，视粒度）。

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `event_id` | `TEXT` | 主键 | 事件主键 |
| `trace_id` | `TEXT` | 非空 | 全链路追踪 ID |
| `user_id` | `TEXT` | 可空 | 用户（可能为系统调用，因此可空） |
| `scenario` | `TEXT` | 非空 | 召回场景：`browse` / `flashcard` / `practice` / `interview` / `dedup_grouping` / `graphrag_qa` 等 |
| `query_text` | `TEXT` | 可空 | 原始 query（可能很短或不存在） |
| `query_intent_json` | `TEXT` | 可空 | 意图识别结果 |
| `hard_filter_json` | `TEXT` | 可空 | 硬过滤条件（公司/岗位/难度等） |
| `recall_path` | `TEXT` | 非空 | 召回路径：`graphrag_main` / `vector_fallback` / `hybrid` |
| `candidates_json` | `TEXT` | 可空 | 候选列表（含 q_id、来源、原始分数） |
| `rerank_method` | `TEXT` | 可空 | 重排方式：`rule` / `llm_rerank` / `cross_encoder` |
| `final_q_ids_json` | `TEXT` | 可空 | 最终输出的 q_id 列表（按顺序） |
| `latency_ms` | `INTEGER` | 可空 | 端到端耗时 |
| `error_msg` | `TEXT` | 可空 | 失败原因 |
| `created_at` | `DATETIME` | 非空 | 写入时间 |

索引：`(trace_id)`、`(scenario, created_at)`、`(user_id, created_at)`

---

## 3. `concept_review_log`

概念审核记录，每次决策一行。

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `review_id` | `TEXT` | 主键 | 审核记录主键 |
| `concept_id` | `TEXT` | 非空 | 被审核的概念节点 ID（Neo4j 节点 id 或自定义业务 ID） |
| `concept_name` | `TEXT` | 非空 | 概念名（冗余，方便检索） |
| `trigger_source` | `TEXT` | 非空 | 触发来源：`auto_dedup` / `auto_belongs_to_fail` / `community_detection` / `llm_audit` / `manual` |
| `action` | `TEXT` | 非空 | 决策：`merge` / `keep` / `re_parent` / `deprecate` / `skip` |
| `target_concept_id` | `TEXT` | 可空 | merge / re_parent 的目标节点 |
| `reviewer_user_id` | `TEXT` | 可空，外键 | 审核人（管理员） |
| `review_note` | `TEXT` | 可空 | 备注 |
| `llm_suggestion` | `TEXT` | 可空 | LLM 建议（用于参考） |
| `created_at` | `DATETIME` | 非空 | 决策时间 |

索引：`(concept_id, created_at)`、`(trigger_source, created_at)`

---

## 4. `llm_call_audit`

每次 LLM 调用一行。覆盖抽取 / 概念去重 / 评分 / 追问等所有调用。

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `call_id` | `TEXT` | 主键 | 调用主键 |
| `trace_id` | `TEXT` | 非空 | 链路追踪 |
| `caller` | `TEXT` | 非空 | 调用方：`extraction-worker` / `interviewer-agent` / `evaluator-agent` / `graph-builder` / `playground` 等 |
| `purpose` | `TEXT` | 非空 | 用途：`extract_questions` / `dedup_concept` / `score` / `followup` / `embed` 等 |
| `model_provider` | `TEXT` | 非空 | `openai` / `deepseek` / `anthropic` |
| `model_name` | `TEXT` | 非空 | 具体模型 |
| `prompt_version_id` | `TEXT` | 可空，外键 | 关联 [2.4 prompt_versions](2.4-Prompt版本与Playground表.md) |
| `token_input` | `INTEGER` | 可空 | 输入 token |
| `token_output` | `INTEGER` | 可空 | 输出 token |
| `cost_usd` | `REAL` | 可空 | 费用估算 |
| `latency_ms` | `INTEGER` | 可空 | 耗时 |
| `status` | `TEXT` | 非空 | `success` / `parse_failed` / `timeout` / `rate_limited` / `error` |
| `error_msg` | `TEXT` | 可空 | 失败原因 |
| `created_at` | `DATETIME` | 非空 | 写入时间 |

索引：`(trace_id)`、`(caller, created_at)`、`(model_provider, model_name, created_at)`

## 5. 数据保留与清理

| 表 | 保留时长 | 清理策略 |
|---|---|---|
| `retrieval_event` | 30 天热数据 + 90 天冷归档 | 30 天后压缩归档（CSV / Parquet），原表删除 |
| `concept_review_log` | 永久 | 不清理（量小、有审计价值） |
| `llm_call_audit` | 30 天热数据 + 180 天冷归档 | 同上 |

## 6. 写入注意事项

- **异步写入**：通过日志中间件（如 Logback Appender）或 RabbitMQ → 专用 audit-worker 写入，主请求不等待。
- **批量写入**：高频场景（如 retrieval_event）支持批量插入。
- **失败降级**：写入失败时只记日志，不影响业务流程。

---

## 7. 隐私

- `query_text` 不应包含未经脱敏的用户敏感信息。
- 个人项目场景敏感性较低，但部署到多用户网站后需 review。
